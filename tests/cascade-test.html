Style application cascade test suite

Tests LVStyleSheet::apply() in lvstsheet.cpp, which flattens all selector chains into an already cascade-ordered list. These cases cover the risky bits: look-alike classes, cross-group source order, pseudo-elements, attribute/universal leading rules, and combinators. The cascade (specificity, source order, pseudo-elements) must behave exactly as before.

1. Classes stay separate

each class matches its own color; look-alikes must not.
expected: green is green-bordered, red red, blue blue; redd, blue2, greenish get no border.
green
red
blue
redd (no border)
blue2 (no border)
greenish (no border)

2. Source order wins

.pink and .violet have equal specificity.
expected: violet text (later source rule wins) regardless of class order.
pink violet
violet pink (still violet)

3. Specificity beats order

#s3 .shallow (0,2,0) is defined before .deep (0,1,0); both match.
expected: green border.
deep shallow

4. Class + pseudo-element selectors

regression: a class-leading ::before/ ::after must still apply (pseudo-element nodes carry no class).
expected: note shows "[NOTE] ... [end]"; warn shows "!!"; note warn shows "!! ... [end]" (the later .warn::before overrides content, as there is one ::before box).
this is a note
this is a note and a warning
this is a warning

second child of .probe — must NOT be italic.

attribute, element-name, and universal leading rules always apply.

7. Class-leading combinators

regression: a class-leading rule with more selectors to its left (#s7 .quote, #s7 div .quote) must cascade correctly. The first quote sits directly inside <section id="s7"> (no div ancestor), so only #s7 .quote applies (gray). The second is wrapped in a <div>, so #s7 div .quote also applies (orange).

element-name leading rules and class rules must interleave by specificity.
