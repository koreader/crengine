small-caps / all-small-caps test suite

Exercises font-variant-caps: small-caps and all-small-caps across the four code paths crengine can take for them: native GSUB, synthesis from a smaller font instance, uppercase folding onto the font's own smcp, and no-op. The uppercase-folding path is what commit lvfntman: fake c2sc added, so sections C and D are the ones that are new; A, B and E are the regression surface around it.

Two of the sections need fonts that are unusual enough that you have to supply them; the @font-face rules and a recipe are in the comment at the top of this file's <style>. Any specimen that renders monospaced is a missing font, not a result.

D. smcp but no c2sc — uppercase folding

The new path. small-caps is untouched by it (the font's own smcp handles that natively). For all-small-caps, crengine rewrites each uppercase character to its lowercase counterpart and lets the font's smcp — enabled alongside the +c2sc that the font ignores — map it to a small cap. No second font instance is involved, so nothing should be shrunk, re-weighted, or shifted off the baseline.

Expected: row 3 is true small caps throughout, at the same weight and height as row 2's small caps. Any letter appearing as a real lowercase glyph means the fold found no smcp mapping for it.

D3. Where folding can show real lowercase

The fold hands a lowercase character to the font and trusts smcp to map it back up. Where smcp does not cover that character, nothing maps it back and the reader sees an actual lowercase letter — whereas native c2sc, lacking coverage, leaves the capital alone. So the two paths fail differently: native degrades to unchanged capitals, folding degrades to changed case. A font will usually cover whatever its smcp was drawn for (Latin, typically) and no more, so these rows are where you find out how far that goes.

With a font derived from Noto Serif, all three rows below fold into visible lowercase, because its smcp covers Latin only even though the feature is registered under cyrl and grek too. Compare each pair: the native line keeps its capitals, the folded one does not.

Greek. Also note that the final sigma of ΛΟΓΟΣ folds to σ and never to ς, the mapping being context-free; with a Greek-covering smcp that still lands on a small-cap sigma, so it would not show.

E5. Nesting and resetting

Inside an all-small-caps paragraph. crengine keeps font-variant values from several properties in one bitmap and deliberately ORs a node's own bits into the inherited ones instead of replacing them (see the comment in setNodeStyle(), lvrend.cpp), so the spec's "the inner value replaces the outer one" does not apply here. Expected: the small-caps span inherits the outer all-small-caps and stays all-small-caps — ACME no taller than its neighbours; the normal span, the documented way out, is ordinary mixed-case text; the rest of the paragraph is unaffected.

Outer ACME text, inner small-caps ACME span, inner normal ACME span, outer ACME again.

Size changes inside the run. Expected: each size gets its own correctly folded instance — small caps at every size, all sitting on the same baseline.

F. Re-render and cache

Font instances are cached per (size, weight, style, features) key, and the wrapper is part of what gets cached. Worth running twice: change the font size or the kerning mode, let the document re-render, and compare against the first pass — sections A, C and D should come back identical. Reopening the file from a saved render cache should as well.
